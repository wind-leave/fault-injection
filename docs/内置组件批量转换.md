# 将内置组件转换成单文件自动发现组件

脚本：`tools/convert_builtin_components.py`。

它读取 `backend/builtin_modules/manifest.json`、对应的 Python 源码以及前端 `componentRegistry.js` 的端口定义，输出“`COMPONENT` 声明 + 原计算代码”的单文件组件。转换过程使用 Python 标准库和本机 Node.js，无需联网或安装新的依赖。

## 批量生成

在项目根目录运行：

```powershell
python tools/convert_builtin_components.py
```

默认生成到 `output/converted_components/`，不会自动加入正在使用的组件库。结果包括：

```text
output/converted_components/
  __init__.py
  auto_gain.py
  auto_11.py
  auto_rf_complex_envelope_limiter.py
  ...
  conversion-report.json
```

新 ID 默认加 `auto_` 前缀，例如 `gain` → `auto_gain`、`11` → `auto_11`，避免与现有清单中的 ID 冲突。仿真组件和电气组件默认保留原一级分组与二级菜单，无需额外参数：脚本读取 `paletteMenu` 或 `simulationMenu`，将菜单 ID 写入生成文件的 `paletteMenu`，将界面实际显示的菜单名称写入 `category`，支持内置菜单和自定义菜单。没有前端模板或分类资料时，才使用“仿真组件 → 内置组件转换”作为默认分类。转换生成的是新 ID 的组件，不设置 `replacesBuiltin`。

例如，原来位于“仿真组件 → 射频信号模型”的组件，生成后声明中包含：

```python
"group": "simulation",
"paletteMenu": "rf-signal",
"category": "射频信号模型",
```

“信号处理模型”对应 `signal-processing`；电气组件的“电源模块”对应 `power-source`，“电能变换”对应 `power-conversion`。内置菜单的显示名称以当前平台注册的名称为准。

使用 `--frontend-json` 时，资料应包含 `group`、`paletteMenu`（也接受旧字段 `simulationMenu`）以及 `category` 或菜单名称字段。旧资料缺少菜单信息时，脚本无法恢复原菜单；可重新导出前端资料或通过 `--overrides` 补充。`--overrides` 可同时设置 `paletteMenu` 和 `category` 来指定自定义菜单；只有 `category`、没有菜单 ID 时，平台按分类名称创建二级菜单。

## 只转换指定组件

`--module` 使用清单里的 **moduleId**，可以重复指定；例如组件“11”的 Python 源文件是 `signal_fanout7.py`，选择时仍应写 `--module 11`。

```powershell
python tools/convert_builtin_components.py --module gain --module 11
```

## 加入自动组件库

将需要的生成文件复制到 `backend/auto_components/`，或者直接指定输出目录：

```powershell
python tools/convert_builtin_components.py --module gain --output-dir backend/auto_components
```

省略 `--module` 可将清单中全部组件生成到该目录。然后重启后端、刷新页面，在对应仿真或电气分类中使用新组件。转换不修改原有组件和旧模型的绑定。默认目录已提供四个保留原 ID 的外部电气组件；如果只想修改这四个组件，直接编辑这些文件即可，详见 [外部电气组件](Python组件自动发现.md#外部电气组件)。

包含本次自动发现扩展的后端需要同步到目标设备。前端无需增加组件注册项。共享计算函数（如 `backend/simulation_functions.py`）仍由平台提供；生成文件并非脱离平台运行的独立程序。

## 重复执行和覆盖

- 目标文件与本次生成内容相同：记为 `unchanged`。
- 目标文件已经存在但内容不同：记为 `skipped`，保留已有文件。
- 明确需要重新生成时添加 `--overwrite`，例如：

```powershell
python tools/convert_builtin_components.py --module gain --overwrite
```

`--overwrite` 会替换所选组件的目标文件，执行前应备份自己在生成文件中的修改。源目录中的 Python 文件和原白名单不会被脚本改写。

## 报告和需要人工确认的情况

`conversion-report.json` 逐项记录原 ID、新 ID、文件名、状态、错误和警告。

- 前端已定义的数值向量、复数包络及固定路数会保留；参数默认值、上下限、枚举及整数类型来自后端清单。
- 没有前端模板的组件，依据清单生成标量端口，暂用变量名作为端口名称，并默认不要求电源。报告会明确提示人工核对；也可以通过 `--overrides` 补充准确资料后重新生成。
- 前端端口名与清单不一致时记为 `failed`，不会生成错误组件。
- 未登记到清单的文件不会猜测接口，会记录在 `unregisteredFiles`。当前目录的 `Test.py` 属于此情况，应先整理函数和接口声明，再按自动发现格式手工补齐；`--module Test` 也不会绕过该检查。
- 每个源文件必须恰好定义一次入口函数；相对导入会改成指向原内置包的绝对导入，以保留共享辅助函数依赖。
- 转换后仍需用实际模型验证参数、故障作用位置、电源接口和信号语义。

例如补充端口显示名与向量长度的 `overrides.json`（键使用原 ID）：

```json
{
  "passthrough": {
    "name": "自定义传递组件",
    "requiresPower": false,
    "inputs": [{"varName": "input", "name": "输入信号", "type": "vector", "dataType": "vector", "vectorLength": 3}],
    "outputs": [{"varName": "output", "name": "输出信号", "type": "vector", "dataType": "vector", "vectorLength": 3}]
  }
}
```

```powershell
python tools/convert_builtin_components.py --module passthrough --overrides overrides.json
```

其他选项：`--id-prefix converted_` 修改新 ID 前缀；`--node` 指定本机 Node.js 路径；`--frontend-json` 使用事先准备的前端元数据 JSON，代替运行 Node.js 读取注册表。所有选项可通过 `--help` 查看。

退出码：全部所选组件生成或保持不变时为 `0`；存在失败或因目标文件冲突而跳过时为 `1`；参数、输入文件或环境错误时为 `2`。未登记文件只记录在报告，不影响已登记组件的批量转换。

## 验证

```powershell
python -m unittest backend.tests.test_convert_builtin_components backend.tests.test_component_discovery -v
npm.cmd test -- --run tests/discovered-component-catalog.spec.js
```

当前清单中的 49 个组件已成功转换。自动测试使用标量、数值向量、复数包络等测试输入，对转换前后组件连续 3 步调用的输出、状态及中间变量做一致性比较；这些验证不能替代实际模型中的完整工况验证。
