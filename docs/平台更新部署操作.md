# 故障注入平台更新部署操作

本文档用于记录当前线上故障注入平台的部署结构和后续更新步骤。

## 1. 当前部署方式

当前平台采用：

```text
1Panel 静态网站 + Python 后端服务 + OpenResty/Nginx 反向代理
```

线上访问地址：

```text
https://simulation-aienglearn.phm-ate.com
```

服务器目录结构：

```text
/opt/1panel/www/sites/simulation-aienglearn.phm-ate.com/
  index/          # 前端静态文件，放本地 dist/ 构建产物
  backend_app/    # 后端代码目录
    backend/
      server.py
      simulation_engine.py
      graph_compiler.py
      module_registry.py
      builtin_modules/
      ...
```

后端服务由 systemd 管理：

```text
fault-simulation-backend.service
```

后端监听服务器本机端口：

```text
127.0.0.1:8766
```

外部访问不直接访问 `8766`，统一通过域名下的接口路径访问：

```text
https://simulation-aienglearn.phm-ate.com/api/simulations
https://simulation-aienglearn.phm-ate.com/api/practice
```

当前不再部署旧接口：

```text
/api/python-flow/execute
```

也不再需要旧的 `8765` 服务。

## 2. 更新前端

前端建议在本地 Windows 电脑上构建，然后用 WinSCP 上传到服务器。

### 2.1 本地构建

在 PowerShell 中执行：

```powershell
cd D:\项目方案\故障注入
npm ci
npm run build
```

构建成功后会生成：

```text
D:\项目方案\故障注入\dist
```

### 2.2 上传前端文件

用 WinSCP 连接服务器，将本地：

```text
D:\项目方案\故障注入\dist\里面的所有文件
```

上传并覆盖服务器目录：

```text
/opt/1panel/www/sites/simulation-aienglearn.phm-ate.com/index/
```

注意：上传的是 `dist` 里面的内容，不是把整个 `dist` 文件夹上传进去。

正确结构应类似：

```text
index/
  index.html
  assets/
  model-packages/
  samples/
```

不要变成：

```text
index/
  dist/
    index.html
```

### 2.3 前端验证

浏览器访问：

```text
https://simulation-aienglearn.phm-ate.com
```

确认页面能正常打开。

## 3. 更新后端

后端更新方式是：备份旧 `backend/`，上传新版 `backend/`，调整权限，重启服务，测试接口。

### 3.1 登录服务器

在 Windows PowerShell 中执行：

```powershell
ssh 用户名@服务器公网IP
```

如果使用非默认端口：

```powershell
ssh -p 端口 用户名@服务器公网IP
```

### 3.2 备份旧后端

登录服务器后执行：

```bash
cd /opt/1panel/www/sites/simulation-aienglearn.phm-ate.com/backend_app
sudo cp -a backend backend.bak.$(date +%Y%m%d%H%M)
```

备份目录示例：

```text
backend.bak.202608121430
```

### 3.3 上传新版后端

用 WinSCP 上传本地目录：

```text
D:\项目方案\故障注入\backend
```

覆盖服务器目录：

```text
/opt/1panel/www/sites/simulation-aienglearn.phm-ate.com/backend_app/backend
```

上传后应保持如下结构：

```text
backend_app/
  backend/
    server.py
    simulation_engine.py
    graph_compiler.py
    module_registry.py
    builtin_modules/
    tests/
    __init__.py
```

不要把 `backend` 里的文件散放到 `backend_app/` 根目录。

### 3.4 调整后端权限

上传完成后执行：

```bash
sudo chown -R www-data:www-data /opt/1panel/www/sites/simulation-aienglearn.phm-ate.com/backend_app
```

原因：后端 systemd 服务使用 `www-data` 用户运行。调整权限可以确保服务能够读取和导入后端代码。

### 3.5 重启后端服务

执行：

```bash
sudo systemctl restart fault-simulation-backend
sudo systemctl status fault-simulation-backend
```

看到：

```text
active (running)
```

说明服务启动成功。

如果服务启动失败，查看日志：

```bash
sudo journalctl -u fault-simulation-backend -n 100 --no-pager
```

## 4. 测试接口

### 4.1 测试仿真接口

执行：

```bash
curl -X POST https://simulation-aienglearn.phm-ate.com/api/simulations/run \
  -H "Content-Type: application/json" \
  -d '{}'
```

如果返回类似：

```json
{"runId":"run-xxxx","status":"error","errorCode":"INVALID_SCHEMA","field":"schemaVersion","message":"schemaVersion must be 1"}
```

说明请求已经到达后端，接口代理是通的。该错误只是因为测试请求体 `{}` 缺少正式仿真数据。

### 4.2 测试练习接口

执行：

```bash
curl -X POST https://simulation-aienglearn.phm-ate.com/api/practice/session \
  -H "Content-Type: application/json" \
  -d '{}'
```

正常情况下也应返回 JSON 错误，而不是 HTML 页面、502 或连接失败。

### 4.3 判断结果

常见结果含义：

```text
返回 INVALID_SCHEMA：接口已通，测试数据不完整。
返回 502 Bad Gateway：后端服务未启动，或反向代理地址错误。
返回 HTML 页面：反向代理未命中，请求被当成前端页面处理。
返回 SSL 错误：HTTPS 证书配置异常。
返回 Connection refused：本机 8766 后端服务未监听。
```

## 5. 1Panel 反向代理配置

网站类型保持：

```text
静态网站
```

不需要改成 Node、Python 或 PHP 网站。

在 1Panel 中进入：

```text
网站 -> 网站 -> simulation-aienglearn.phm-ate.com -> 配置 -> 反向代理
```

应保留两个反向代理：

```text
名称：simulations
前端请求路径：/api/simulations
后端代理地址：http://127.0.0.1:8766
```

```text
名称：practice
前端请求路径：/api/practice
后端代理地址：http://127.0.0.1:8766
```

如果 1Panel 的表单是“协议下拉框 + 地址输入框”，则：

```text
协议选择：http
地址填写：127.0.0.1:8766
```

不要在地址输入框里重复填写 `http://`，否则可能生成错误配置。

不需要配置：

```text
/api/python-flow
```

## 6. HTTPS 证书检查

证书必须覆盖：

```text
simulation-aienglearn.phm-ate.com
```

或者使用能覆盖该域名的通配符证书：

```text
*.phm-ate.com
```

不能使用其他域名证书，例如：

```text
*.ailabs.de5.net
```

证书更新后测试：

```bash
curl -I https://simulation-aienglearn.phm-ate.com
```

如果不再出现证书不匹配错误，说明 HTTPS 证书配置正常。

## 7. 常用维护命令

查看后端服务状态：

```bash
sudo systemctl status fault-simulation-backend
```

重启后端服务：

```bash
sudo systemctl restart fault-simulation-backend
```

查看后端日志：

```bash
sudo journalctl -u fault-simulation-backend -n 100 --no-pager
```

直接测试服务器本机后端：

```bash
curl -X POST http://127.0.0.1:8766/api/simulations/run \
  -H "Content-Type: application/json" \
  -d '{}'
```

测试公网域名代理：

```bash
curl -X POST https://simulation-aienglearn.phm-ate.com/api/simulations/run \
  -H "Content-Type: application/json" \
  -d '{}'
```

## 8. 完整更新流程摘要

前端更新：

```text
本地 npm run build -> 上传 dist/ 里面的所有文件 -> 覆盖服务器 index/
```

后端更新：

```text
服务器备份 backend/ -> WinSCP 上传新版 backend/ -> chown 给 www-data -> 重启 fault-simulation-backend -> curl 测试接口
```

最终确认：

```text
1. 页面能打开。
2. 后端服务 active (running)。
3. /api/simulations 返回 JSON。
4. /api/practice 返回 JSON。
5. HTTPS 证书无错误。
```
