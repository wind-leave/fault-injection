# 工程仿真型故障注入网页平台设计

## 1. 目标与边界

第一版目标是建设一个外网可访问的工程仿真型故障注入网页平台。用户打开网页即可使用，不需要登录。平台聚焦 UAV/eVTOL 飞控系统，优先保证界面工作流顺畅，同时具备工程分析级模型可信度和基础外网安全防护。

第一版不是纯演示 Demo，也不是完整账号体系平台。项目数据、故障配置和仿真结果主要保存在浏览器本地，用户可手动导入导出。服务器不长期保存用户项目和仿真结果，只负责发布网页、运行内置白名单 Python 仿真模型、提供外部系统接口和匿名服务日志。

第一版不支持用户上传 Python 代码、自定义公式、新模型拓扑或任意组件。模型能力先以内置 eVTOL 闭环飞控模型为主，后续再扩展模型导入、异步任务、WebSocket 实时流、账号权限和正式工程报告。

## 2. 用户与主要场景

平台面向工程仿真、方案验证和故障影响分析人员。第一版核心场景包括：

- 用户在网页中配置一版 eVTOL 飞控基线模型。
- 用户修改模型参数、测点、模块启停和同接口内置组件替换。
- 用户在同一模型上配置多个故障实例，并设置启用状态、开始时间和持续时间。
- 用户运行单次仿真，查看事件时间线、基础曲线、事件局部曲线和指标摘要。
- 用户导出项目、仿真结果和基础报告。
- 用户将基线配置导出为 JSON，或通过后端预配置接口推送给外部系统。
- 外部系统基于基线配置初始化后，修改模型参数和故障参数，再调用仿真 API 获取结果。

## 3. 总体架构

系统由浏览器前端、Python 后端 API、内置仿真模型库、外部系统对接能力组成。

```text
浏览器前端 Vue
  - 模型工作台
  - 故障配置
  - 浏览器本地项目保存
  - 基线导出与推送触发
  - 结果展示与报告导出

Python 后端 API
  - 前端仿真接口
  - 外部系统仿真接口
  - 基线配置推送代理
  - 内置模型白名单
  - 参数与故障方案校验
  - 同步短任务仿真执行
  - 资源限制、频率限制、并发限制
  - 匿名服务日志

外部系统
  - 接收基线配置初始化
  - 修改模型参数和故障参数
  - 携带 API Key 调用仿真 API
  - 接收同步仿真结果
```

关键边界：

- 网页用户不登录。
- 机器接口需要 API Key，可选 IP 白名单。
- 外部系统地址和凭证由平台后端预配置，不暴露给浏览器。
- 后端只运行内置模型、内置组件和内置故障类型。
- 后端不长期保存用户项目、故障配置、曲线结果或报告。

## 4. 前端功能模块

### 4.1 模型工作台

模型工作台展示内置 UAV/eVTOL 飞控系统结构。第一版允许有限编辑：

- 修改模型参数。
- 添加或删除测点。
- 启用或禁用模块。
- 替换同接口内置组件。
- 查看模型模块、参数和适用边界说明。

第一版不允许任意拖拽搭建新拓扑，不允许上传外部 Python 组件。

### 4.2 故障方案

故障库按层级组织：

- 物理层。
- 电气/信号层。
- 软件/控制层。

故障配置采用画布可视化标签和表单参数编辑结合的方式。每个故障实例包含：

- 故障 ID。
- 故障层级。
- 故障类型。
- 目标对象。
- 启用状态。
- 开始时间。
- 持续时间。
- 参数集合。

第一版允许同一模型上配置多个故障，支持同时生效和按时间触发。第一版不做故障冲突检查，但界面需要提示用户自行确认复合故障合理性，并在数据模型中预留冲突规则扩展点。

### 4.3 基线下发

网页支持两种基线下发方式，第一版都要实现：

- 导出基线配置 JSON 文件。
- 点击按钮将基线配置推送到预配置外部系统。

用户不需要也不能在网页中配置外部系统地址或密钥。推送动作由前端请求本平台后端，后端读取部署时预配置的外部系统 endpoint、凭证和超时参数，再代理转发基线配置。

网页显示最近一次推送状态和失败原因。失败类型包括地址不可达、鉴权失败、超时、外部系统返回格式错误、外部系统拒绝配置。

### 4.4 仿真结果

结果展示以事件时间线为主，同时提供基础曲线总览和事件局部曲线。

事件包括：

- 故障开始。
- 故障结束。
- 姿态超限。
- 控制饱和。
- 失稳判定。
- 告警触发。
- 用户人工标注。

曲线至少支持关键飞控通道，例如姿态角、角速度、电机输出、传感器输出或控制指令。事件详情中展示事件附近局部曲线，便于解释事件发生原因。

### 4.5 项目与报告

项目主要保存在浏览器本地，并支持手动导入导出。导出内容包括：

- 模型配置。
- 故障配置。
- 测点配置。
- 仿真参数。
- 最近仿真结果。
- 用户标注。

基础报告导出包含模型信息、仿真参数、故障配置、基线版本、事件时间线、关键曲线、指标摘要和用户标注。正式工程报告、审签流程和附件管理放到后续阶段。

## 5. 后端功能模块

### 5.1 前端仿真接口

前端仿真接口接收网页提交的模型参数、故障方案和仿真配置。后端校验后同步运行内置 Python 模型，并返回事件、曲线、指标和告警。

### 5.2 外部系统仿真接口

外部系统仿真接口接收外部系统提交的模型参数覆盖、故障参数覆盖和仿真配置。外部系统可以修改：

- 模型参数。
- 故障参数。
- 故障启用状态。
- 故障开始时间和持续时间。
- 仿真时长和步长。

外部系统不允许提交：

- 外部时序数据。
- 外部工况数据。
- 新模型拓扑。
- 新组件。
- Python 代码。
- 自定义公式。

外部系统仿真接口需要 API Key，可选 IP 白名单。结果只同步返回给外部系统，网页端不自动接收这类结果。

### 5.3 基线推送代理

基线推送代理由网页触发。后端读取预配置外部系统连接信息，将当前基线配置转发给外部系统初始化接口，并返回推送状态给网页。

### 5.4 内置模型与故障白名单

后端只允许运行服务器内置模型、内置组件和内置故障类型。每个模型、组件、故障类型和参数都要有明确白名单和范围校验。

## 6. 数据设计

### 6.1 项目文件

项目文件建议使用 JSON：

```json
{
  "schemaVersion": 1,
  "projectId": "local-project-001",
  "modelId": "evtol-flight-control-v1",
  "modelParameters": {},
  "enabledModules": {},
  "componentReplacements": {},
  "measurementPoints": [],
  "faultInstances": [],
  "simulationConfig": {},
  "lastResult": null,
  "annotations": []
}
```

### 6.2 基线配置

基线配置用于导出文件和推送外部系统：

```json
{
  "schemaVersion": 1,
  "baselineId": "baseline-001",
  "modelId": "evtol-flight-control-v1",
  "modelVersion": "1.0.0",
  "modelParameters": {},
  "enabledModules": {},
  "componentReplacements": {},
  "measurementPoints": [],
  "faultProfile": {
    "faultInstances": []
  },
  "simulationConfig": {
    "duration": 10,
    "stepSize": 0.01
  }
}
```

### 6.3 故障实例

故障实例格式统一用于网页仿真、基线配置和外部系统仿真接口：

```json
{
  "faultId": "fault-001",
  "layer": "signal",
  "faultType": "sensor_bias",
  "targetType": "signal",
  "targetId": "imu.gyro_z",
  "enabled": true,
  "startTime": 3.0,
  "duration": 5.0,
  "parameters": {
    "bias": 0.08
  }
}
```

### 6.4 外部系统仿真请求

外部系统回传仿真请求时只提交参数覆盖和故障参数：

```json
{
  "modelId": "evtol-flight-control-v1",
  "baseConfigVersion": "baseline-001",
  "modelParameterOverrides": {
    "controller.kp_pitch": 1.2,
    "motor.m1.efficiency": 0.85
  },
  "faultProfile": {
    "faultInstances": [
      {
        "faultId": "fault-001",
        "faultType": "sensor_bias",
        "targetId": "imu.gyro_z",
        "enabled": true,
        "startTime": 3.0,
        "duration": 5.0,
        "parameters": {
          "bias": 0.08
        }
      }
    ]
  },
  "simulationConfig": {
    "duration": 10,
    "stepSize": 0.01
  }
}
```

### 6.5 仿真结果

后端返回结构：

```json
{
  "runId": "run-001",
  "status": "success",
  "events": [
    {
      "time": 3.0,
      "type": "fault_started",
      "severity": "info",
      "message": "IMU gyro bias fault started",
      "relatedFaultId": "fault-001"
    }
  ],
  "curves": {
    "time": [0, 0.01, 0.02],
    "channels": {
      "attitude.pitch": [0, 0.01, 0.03],
      "motor.m1.thrust": [2.1, 2.2, 2.3]
    }
  },
  "metrics": {
    "maxPitchError": 0.12,
    "saturationCount": 3
  },
  "warnings": []
}
```

## 7. 主要数据流

### 7.1 网页人工仿真

```text
用户打开网页
-> 配置内置 eVTOL 模型
-> 配置多个故障实例
-> 设置故障触发时间
-> 前端提交模型参数、故障方案、仿真配置
-> 后端校验白名单和参数范围
-> 后端运行 Python 仿真
-> 返回事件、曲线和指标
-> 网页展示结果
-> 用户导出项目、结果或基础报告
```

### 7.2 外部系统闭环仿真

```text
用户在网页配置基线模型
-> 网页导出基线 JSON，或通过后端推送基线到外部系统
-> 外部系统用基线配置初始化
-> 外部系统修改模型参数和故障参数
-> 外部系统携带 API Key 调用仿真 API
-> 后端校验 API Key、IP、模型 ID、参数和故障白名单
-> 后端同步运行 Python 仿真
-> 结果返回给外部系统
```

## 8. 错误处理

前端需要将错误转换为用户可理解的说明，至少覆盖：

- 模型配置不完整。
- 故障目标不存在。
- 参数超出范围。
- 仿真请求超时。
- 后端校验失败。
- 基线推送失败。
- 项目导入格式错误。
- 报告生成失败。

后端错误统一返回结构化错误码、错误字段和修正建议。例如：

```json
{
  "status": "error",
  "errorCode": "PARAM_OUT_OF_RANGE",
  "field": "faultProfile.faultInstances[0].parameters.bias",
  "message": "bias must be within [-1, 1]"
}
```

## 9. 安全与资源限制

第一版必须实现以下限制：

- 最大请求体大小。
- 最大故障实例数。
- 最大测点数。
- 最大仿真时长。
- 最小和最大步长。
- 单次执行超时。
- 同时执行数量限制。
- 单 IP 调用频率限制。
- 外部接口 API Key。
- 可选 IP 白名单。

服务器不保存完整项目、完整故障方案、曲线结果或报告。服务日志只保存请求时间、接口类型、模型 ID、耗时、成功/失败、错误码、IP 摘要和资源限制命中情况。

## 10. 模型可信度与文档

第一版目标为工程分析级，后续向验证评估级演进。每个模型模块、参数和故障类型都需要界面内说明和工程文档说明。

工程文档至少覆盖：

- 模型假设。
- 方程或计算逻辑。
- 参数来源。
- 故障机理。
- 参数范围。
- 适用边界。
- 指标定义。
- 事件判定逻辑。

## 11. 测试与验收

### 11.1 工作流验收

必须跑通：

- 打开网页。
- 选择内置 eVTOL 模型。
- 修改模型参数。
- 配置多个故障。
- 设置故障触发时间。
- 运行仿真。
- 查看事件时间线。
- 查看基础曲线和事件局部曲线。
- 添加人工标注。
- 导出项目。
- 导出基础报告。
- 导出基线 JSON。
- 推送基线到预配置外部系统。
- 外部系统调用仿真 API 并获得结果。

### 11.2 模型与故障验收

第一版至少覆盖：

- 传感器故障：零偏、漂移、噪声、卡死。
- 执行机构故障：电机效率下降、单电机失效、响应迟滞。
- 控制/软件故障：控制增益异常、指令限幅异常、控制指令偏置。

每个故障需要具备参数范围、作用目标、触发时间、持续时间、事件输出、曲线影响和文档说明。

### 11.3 接口验收

后端 API 至少验证：

- 合法请求能返回仿真结果。
- 非法 modelId 被拒绝。
- 非法故障类型被拒绝。
- 参数越界被拒绝。
- 请求体过大被拒绝。
- 仿真时长超限被拒绝。
- 外部接口缺少 API Key 被拒绝。
- IP 白名单生效。
- 并发限制生效。

### 11.4 前端验收

前端至少验证：

- 项目导入导出后内容一致。
- 多个故障实例能正确显示和编辑。
- 故障启用和禁用生效。
- 参数越界能提示。
- 仿真失败能显示明确原因。
- 事件时间线能定位局部曲线。
- 报告包含模型、故障、事件、曲线、指标和标注。

### 11.5 性能验收

第一版建议默认目标：

- 单次仿真 10 秒内返回。
- 最大仿真时长 60 秒。
- 最小步长 0.001 秒。
- 最大故障实例数 20。
- 最大测点数 50。
- 最大并发仿真数按服务器配置设定。

这些数值可按实际模型复杂度调整，但产品和接口必须保留上限。
