# 三维实践任务包导出设计

## 目标

将工作台顶部“保存仿真结果”导出的 JSON 改为三维实践任务包。单个文件同时包含 `publicData` 和 `privateData`；本阶段只负责一并导出，不实现权限拆分、后端保存或三维端下发控制。

## 输出结构

顶层保留格式版本、类型、导出时间、任务 ID 和基础元信息，并将业务数据分成：

- `publicData`：渲染数据、三维映射占位和初始实际仿真结果。
- `privateData`：可执行模型、从零重跑配置、目标故障、D 矩阵、初始推荐路径和关键节点。

公开数据不再重复导出模型拓扑；`renderData` 直接位于 `publicData` 下。完整节点、连线和故障能力约束只保留在私有可执行模型中。

导出类型改为 `3d-practice-task-package`。文件名仍沿用 `{datasetName}-{YYYY-MM-DD}.json`，避免改变用户现有保存习惯。

## 数据来源

- 可执行模型调用现有 `buildBackendExecutablePackage()` 生成，不复制第二套节点标准化逻辑。
- 初始渲染数据来自 `SIM.actual`。
- 目标故障优先取当前实践选中的第一个故障。
- 初始推荐路径取目标实践故障的 `troubleshootingPath`。
- 关键节点从推荐路径步骤中提取测点和维修目标；没有路径时为空数组。
- 当前系统没有三维场景对象映射和初始条件配置，因此分别导出空数组或空对象，保留稳定契约供后续填写。

## 已确认的维修语义

- 每次维修基于当前最新模型，从 `t=0` 完整重跑。
- 有效维修累计进入后续模型版本。
- 错误更换也记录并生成模型版本，但不清除真实故障。
- 三维端后续只应提交目标对象，不应依赖公开的故障答案；本阶段私有数据仍与公开数据一起写入文件。

## 兼容与验证

新增独立纯函数服务组装任务包，旧运行时只负责收集工作台状态并调用服务。自动化测试验证公开/私有分区、可执行模型和重跑配置。格式说明文档同步更新。
