# 将内置组件转换成单文件自动发现组件

脚本：`tools/convert_builtin_components.py`。

它读取 `backend/builtin_modules/manifest.json`、对应的 Python 源码以及前端 `componentRegistry.js` 的端口定义，输出“`COMPONENT` 声明 + 原计算代码”的单文件组件。转换过程使用 Python 标准库和本机 Node.js，无需联网或安装新的依赖。

## 转换范围

当前清单通过 `autoConvert` 字段控制是否转换，仅以下四个电气组件设置为 `true`：

| moduleId | 组件 |
| --- | --- |
| `electrical_ac_power_source` | 交流电源模块 |
| `electrical_dc_power_source` | 直流电源模块 |
| `electrical_dc_boost` | 直流升压模块 |
| `electrical_ac_dc_matching` | 直流匹配模块 |

其余 45 个现有条目设置为 `autoConvert: false`，包含当前的旧仿真组件和地面组件；脚本将它们记为 `excluded`，不生成或覆盖对应文件。`--module` 和 `--overwrite` 都不会绕过此开关。

后续新增仿真组件时，将 Python 文件和接口登记到 `manifest.json`。新条目不填写 `autoConvert` 时默认允许转换，也可以明确设置为 `true`；只有 `false` 才禁止转换，字符串 `"false"` 等非布尔值会报错。例如：

```json
{
  "moduleId": "new_simulation",
  "importPath": "backend.builtin_modules.new_simulation",
  "entryFunction": "process",
  "inputs": ["input"],
  "outputs": ["output"],
  "parameters": {}
}
```

`autoConvert` 只控制转换脚本，不影响后端模块注册或执行。电气和仿真分组目前隐藏内置组件、显示外部自动发现组件。

## 批量生成

在项目根目录运行：

```powershell
python tools/convert_builtin_components.py
```

默认生成到 `output/converted_components/`，不会自动加入正在使用的组件库。结果包括：

```text
output/converted_components/
  __init__.py
  electrical_ac_power_source.py
  electrical_dc_power_source.py
  electrical_dc_boost.py
  electrical_ac_dc_matching.py
  conversion-report.json
```

默认保留原 `moduleId` 和前端 `templateId`，不添加 `auto_` 或 `discovered_` 前缀。例如 `gain` 转换后仍是 `gain`，组件“11”仍使用字符串 ID `"11"`。Python 文件名必须是有效标识符，因此数字 ID 等特殊情况沿用原 Python 源文件名，例如 `signal_fanout7.py`；这不改变组件 ID。仿真组件和电气组件默认保留原一级分组与二级菜单，无需额外参数：脚本读取 `paletteMenu` 或 `simulationMenu`，将菜单 ID 写入生成文件的 `paletteMenu`，将界面实际显示的菜单名称写入 `category`，支持内置菜单和自定义菜单。没有前端模板或分类资料时，才使用“仿真组件 → 内置组件转换”作为默认分类。生成声明包含 `replacesBuiltin: True`：目标平台已有同 ID 内置仿真或电气模块时，外部定义和计算实现优先；没有同 ID 内置模块时按新组件加载。不会覆盖界面注册的自定义后端模块。同目录多个外部文件也不能重复声明同一 ID。

例如，原来位于“仿真组件 → 射频信号模型”的组件，生成后声明中包含：

```python
"group": "simulation",
"paletteMenu": "rf-signal",
"category": "射频信号模型",
```

“信号处理模型”对应 `signal-processing`；电气组件的“电源模块”对应 `power-source`，“电能变换”对应 `power-conversion`。内置菜单的显示名称以当前平台注册的名称为准。

使用 `--frontend-json` 时，资料应包含 `templateId`（原前端组件标识；省略时使用 `moduleId`）、`group`、`paletteMenu`（也接受旧字段 `simulationMenu`）以及 `category` 或菜单名称字段。旧资料缺少菜单信息时，脚本无法恢复原菜单；可重新导出前端资料或通过 `--overrides` 补充。`--overrides` 可同时设置 `paletteMenu` 和 `category` 来指定自定义菜单；只有 `category`、没有菜单 ID 时，平台按分类名称创建二级菜单。

## 只转换指定组件

`--module` 使用清单里的 **moduleId**，可以重复指定；所选组件仍须允许自动转换。

```powershell
python tools/convert_builtin_components.py --module electrical_dc_power_source --module electrical_dc_boost
```

## 加入自动组件库

将需要的生成文件复制到 `backend/auto_components/`，或者直接指定输出目录：

```powershell
python tools/convert_builtin_components.py --module electrical_dc_power_source --output-dir backend/auto_components
```

省略 `--module` 会转换清单中所有允许转换的条目；当前只生成上述四个电气组件，后续新增且未关闭转换的仿真组件也会生成。重启后端并刷新页面即可在对应分类看到外部组件；内置组件仍隐藏。同 ID 内置组件由外部定义和计算实现替换，原模型和显控台可以继续引用原 ID。如果另一版本修改了接口，已有模型的端口和参数也必须与该版接口一致，平台不会自动重写模型连线。默认自动发现目录不预装组件；需要时先转换并将生成文件放入该目录，后续可直接编辑外部文件，详见 [外部电气组件](Python组件自动发现.md#外部电气组件)。

包含本次自动发现扩展的后端需要同步到目标设备。前端无需增加组件注册项。共享计算函数（如 `backend/simulation_functions.py`）仍由平台提供；生成文件并非脱离平台运行的独立程序。

## 重复执行和覆盖

- 目标文件与本次生成内容相同：记为 `unchanged`。
- 目标文件已经存在但内容不同：记为 `skipped`，保留已有文件。
- 清单设置 `autoConvert: false`：记为 `excluded`，即使指定 `--overwrite` 也不改写已有文件。以前生成的旧仿真组件文件不会自动删除；要得到仅包含当前允许条目的结果，请输出到一个新的空目录。
- 明确需要重新生成时添加 `--overwrite`，例如：

```powershell
python tools/convert_builtin_components.py --module electrical_dc_power_source --overwrite
```

`--overwrite` 会替换所选组件的目标文件，执行前应备份自己在生成文件中的修改。源目录中的 Python 文件和原白名单不会被脚本改写。

## 报告和需要人工确认的情况

`conversion-report.json` 逐项记录原 ID、新 ID、文件名、状态、错误和警告。

- 前端已定义的数值向量、复数包络及固定路数会保留；参数默认值、上下限、枚举及整数类型来自后端清单。
- 没有前端模板的组件，依据清单生成标量端口，暂用变量名作为端口名称，并默认不要求电源。报告会明确提示人工核对；也可以通过 `--overrides` 补充准确资料后重新生成。
- 前端端口名与清单不一致时记为 `failed`，不会生成错误组件。
- 未登记到清单的文件不会猜测接口，会记录在 `unregisteredFiles`。当前目录的 `Test.py` 属于此情况，应先整理函数和接口声明，再按自动发现格式手工补齐；`--module Test` 也不会绕过该检查。
- 每个源文件必须恰好定义一次入口函数；相对导入会改成指向原内置包的绝对导入，以保留共享辅助函数依赖。
- 转换后仍需用实际模型验证参数、故障作用位置、电源接口和信号语义。

例如补充端口显示名与向量长度的 `overrides.json`（键使用原 ID）：

```json
{
  "new_simulation": {
    "name": "自定义传递组件",
    "requiresPower": false,
    "inputs": [{"varName": "input", "name": "输入信号", "type": "vector", "dataType": "vector", "vectorLength": 3}],
    "outputs": [{"varName": "output", "name": "输出信号", "type": "vector", "dataType": "vector", "vectorLength": 3}]
  }
}
```

```powershell
python tools/convert_builtin_components.py --module new_simulation --overrides overrides.json
```

其他选项：默认保持原 ID；显式使用 `--id-prefix converted_` 才会生成不同 ID 的独立副本，此时模型和显控绑定需自行匹配新 ID；`--node` 指定本机 Node.js 路径；`--frontend-json` 使用事先准备的前端元数据 JSON，代替运行 Node.js 读取注册表。所有选项可通过 `--help` 查看。

退出码：允许转换的组件生成或保持不变时为 `0`，按清单排除的 `excluded` 条目不算失败；存在失败或因目标文件冲突而跳过时为 `1`；参数、输入文件或环境错误时为 `2`。未登记文件只记录在报告，不影响已登记组件的批量转换。
