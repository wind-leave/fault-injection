# 新增仿真组件操作流程

本文用于在故障注入平台中新增一个可以由 Python 后端实际执行的仿真组件。示例组件为“气压高度传感器”，其计算关系为：

```text
measured_altitude = (true_altitude + bias) * scale
```

## 1. 先确定接口

在写代码前，先确定以下内容：

| 项目 | 气压高度传感器示例 | 说明 |
| --- | --- | --- |
| 模块 ID | `barometer_sensor` | 全项目唯一，使用小写英文和下划线 |
| Python 文件 | `barometer_sensor.py` | 放在 `backend/builtin_modules/` |
| 入口函数 | `process` | 后端执行时调用的函数 |
| 输入 | `true_altitude` | 来自组件输入端口的信号 |
| 输出 | `measured_altitude` | 组件输出端口的信号 |
| 参数 | `bias`、`scale` | 节点参数，不是连线输入 |

变量名必须在 Python、后端清单和前端端口配置中保持一致。中文名称仅用于界面展示。

## 2. 新建后端 Python 模块

在 `backend/builtin_modules/` 新建文件，例如 `barometer_sensor.py`：

```python
def process(true_altitude=0.0, bias=0.0, scale=1.0):
    measured_altitude = (float(true_altitude) + float(bias)) * float(scale)
    return {
        "outputs": {
            "measured_altitude": measured_altitude,
        },
    }
```

约定：

- `process` 的业务输入、参数名必须与清单一致。
- 返回值使用字典；输出统一放在 `outputs` 中。
- `outputs` 的键必须与清单的 `outputs` 一致。
- 无状态组件不需要 `state`；有状态组件应通过返回值中的 `state` 保存状态，不要使用模块全局变量。
- 组件自身不要实现随机故障、卡死、突变等故障逻辑；这些由故障运行时统一处理，确保参考曲线不受影响。

## 3. 加入后端模块清单（白名单）

编辑 `backend/builtin_modules/manifest.json` 的 `modules` 数组，添加：

```json
{
  "moduleId": "barometer_sensor",
  "importPath": "backend.builtin_modules.barometer_sensor",
  "entryFunction": "process",
  "inputs": ["true_altitude"],
  "outputs": ["measured_altitude"],
  "parameters": {
    "bias": { "type": "number", "min": -1000, "max": 1000, "default": 0 },
    "scale": { "type": "number", "min": 0, "max": 10, "default": 1 }
  }
}
```

这个清单就是后端可执行模块的白名单和接口契约：

- `moduleId`：前端节点用它选择后端模块。
- `importPath`：Python 模块的导入路径，不带 `.py`。
- `inputs`、`outputs`：后端的端口顺序和变量名依据。
- `parameters`：允许传入的参数、默认值和数值范围。

未加入清单的 Python 文件不会被后端执行。修改清单或 Python 文件后，需要重启后端服务。

## 4. 为后端模块编写测试

新增 `backend/tests/test_barometer_sensor.py`，至少覆盖正常计算和默认参数。例如：

```python
import unittest

from backend.builtin_modules.barometer_sensor import process


class BarometerSensorTests(unittest.TestCase):
    def test_applies_bias_and_scale(self):
        result = process(true_altitude=100.0, bias=2.0, scale=1.1)
        self.assertEqual(result["outputs"]["measured_altitude"], 112.2)
```

执行验证：

```powershell
uv run python -m unittest backend.tests.test_barometer_sensor -v
uv run python -m unittest discover backend.tests -v
```

## 5. 在前端组件库注册模板

编辑 `src/services/componentRegistry.js`，添加一个模板项。模板应包含以下部分：

| 区域 | 必填内容 | 用途 |
| --- | --- | --- |
| 基本信息 | `type`、`templateId`、`group`、`label` | 决定组件库分类和显示 |
| `defaults` | 名称、输入、输出、参数 | 新建节点的初始属性 |
| `ports` | 输入/输出端口 | 画布连线和信号映射 |
| `pythonBinding` | `moduleId`、入口函数、端口映射 | 指向后端白名单模块 |
| `faultSlots` | 参数或信号的可注入位置 | 限定故障实际作用对象 |

最关键的绑定应为：

```js
pythonBinding: {
  bound: true,
  moduleId: 'barometer_sensor',
  fileName: 'barometer_sensor.py',
  moduleName: 'barometer_sensor',
  entryFunction: 'process',
  executionMode: 'backend'
}
```

其中 `moduleId` 必须与 `manifest.json` 中的 `moduleId` 完全一致。`rawSource` 和 `parsedInterface` 主要用于前端展示、编辑和导入信息，后端正式仿真不执行其中的源码。

## 6. 配置端口与参数映射

端口的关键字段示例：

```js
{
  portId: 'input-0',
  signalId: 'barometer_sensor.true_altitude',
  varName: 'true_altitude',
  displayName: '真实高度',
  type: 'float',
  unit: 'm',
  direction: 'input'
}
```

- `portId`：画布中该端口的稳定标识。
- `signalId`：信号的全局标识，建议使用“模块 ID.变量名”。
- `varName`：与 Python 和后端清单对应的英文变量名。
- `displayName`：界面显示名称。
- `type`、`unit`：信号类型和单位。

`portMapping.inputs` 和 `portMapping.outputs` 应使用同一组 `portId`、`signalId`、`varName`，把画布端口映射到后端接口。

参数在 `defaults.parameters` 中声明。例如：

```js
parameters: [
  { key: 'bias', name: '零偏', layer: 'physical', default: 0, unit: 'm' },
  { key: 'scale', name: '比例系数', layer: 'physical', default: 1 }
]
```

参数不是中间变量。中间变量是模型计算过程中的可观测量；参数是运行前或故障运行时修改的配置值。

## 7. 声明故障槽位

对于需要做物理层参数故障的组件，建议明确声明 `faultSlots`。气压高度传感器可配置为：

```js
faultSlots: [
  {
    slotId: 'physical:barometer_bias',
    slotName: '气压高度零偏',
    displayName: '气压高度零偏',
    layer: 'physical',
    kind: 'parameter',
    targetField: 'params.bias',
    allowedModels: ['bias', 'drift', 'step', 'degradation', 'freeze', 'random']
  },
  {
    slotId: 'physical:barometer_scale',
    slotName: '比例系数',
    displayName: '比例系数',
    layer: 'physical',
    kind: 'parameter',
    targetField: 'params.scale',
    allowedModels: ['bias', 'drift', 'step', 'degradation', 'freeze', 'random']
  }
]
```

`targetField` 是核心字段：

- `params.bias` 表示修改 Python 的 `bias` 参数。
- `params.scale` 表示修改 Python 的 `scale` 参数。
- 物理层故障应作用于参数槽位。
- 电气层故障应作用于输入端口、输出端口或连线信号，而不是参数槽位。

新增或修改模板的 `faultSlots` 后，已在画布上创建的旧节点不会自动获得新槽位。应删除旧节点并从组件库重新拖入，或实施专门的数据迁移。

## 8. 前后端联调与验收

1. 重启后端服务，使新的 Python 文件和清单生效。
2. 刷新前端页面；若修改了模板，重新从组件库拖入该组件。
3. 将输入信号连到组件输入端口，将输出连到示波器或下游组件。
4. 不注入故障时，确认实际曲线与参考曲线一致。
5. 注入物理层故障，确认只有实际曲线受影响，参考曲线保持基线。
6. 对输入端口、输出端口和连线分别注入电气层故障，确认影响出现在对应位置之后的信号上。
7. 执行前端构建：

```powershell
npm.cmd run build
```

## 9. 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| 组件在组件库中找不到 | `componentRegistry.js` 的 `group`、`type`、模板注册是否正确 |
| 后端提示未注册模块 | `pythonBinding.moduleId` 是否与 `manifest.json` 完全一致；后端是否已重启 |
| 输出始终为 0 | Python 返回结构、`outputs` 键名、端口 `varName` 是否一致 |
| 修改参数不生效 | 清单中是否声明该参数；节点参数是否正确导出；是否使用清单默认值 |
| 物理层故障不生效 | 故障实例的 `targetField` 是否为 `params.<参数名>`；故障是否处于生效时间窗；旧节点是否缺少新 `faultSlots` |
| 电气层故障不生效 | 故障目标是否为输入端口、输出端口或连线；信号是否真的经过该目标；检查实际曲线而非参考曲线 |
| 页面显示与后端运行结果不一致 | 确认 `executionMode: 'backend'`，并重启后端和刷新浏览器 |

## 10. 提交前检查清单

- [ ] Python 模块位于 `backend/builtin_modules/`。
- [ ] `manifest.json` 已加入唯一的模块 ID 和准确接口。
- [ ] Python 输入、输出、参数名与清单一致。
- [ ] 组件模板已注册到 `componentRegistry.js`。
- [ ] 端口 `varName`、`portMapping` 与后端接口一致。
- [ ] 参数单位、范围、默认值符合模型含义。
- [ ] 需要故障注入的位置已声明准确的 `faultSlots`。
- [ ] 后端单元测试和完整回归测试通过。
- [ ] 前端生产构建通过。
- [ ] 已用新建画布节点完成无故障、物理层故障和电气层故障的联调。
