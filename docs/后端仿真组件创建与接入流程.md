# 后端仿真组件创建与接入流程

## 1. 文档目标

本文档说明如何为故障注入平台新增一个能够在当前 Python 后端实际执行的仿真组件，并完成白名单注册、自动测试、前端画布绑定、API 联调和正式发布。

本文档所说的“后端仿真组件”必须同时满足：

1. 组件节点类型为 `simulation_block`。
2. `pythonBinding.moduleId` 已注册到 `backend/builtin_modules/manifest.json`。
3. 注册项指向一个可导入的 Python 模块和可调用入口函数。
4. 输入、输出、参数和返回结构符合当前 `backend.module_registry` 约定。
5. 组件进入模型包后能够通过 `/api/simulations/run` 或步进会话接口执行。

## 2. 当前执行链和安全边界

```mermaid
flowchart LR
    A[前端画布组件] --> B[导出可执行模型包]
    B --> C[POST /api/simulations/run]
    C --> D[校验模型包]
    D --> E[读取 pythonBinding.moduleId]
    E --> F[manifest.json 白名单]
    F --> G[导入 backend.builtin_modules 模块]
    G --> H[逐时间步调用 process]
    H --> I[实际值/参考值曲线与组件输出]
```

安全边界：

- 前端模型包中的 `pythonModules`、`rawSource` 或其他 Python 源码不会被当前后端执行。
- 后端只执行本机 `backend/builtin_modules/manifest.json` 已注册的模块。
- 仅在前端选择或绑定 `.py` 文件，不等于后端已经安装该组件。
- 新组件必须把后端 `.py` 文件和 `manifest.json` 修改部署到每一台后端机器，并重启后端服务。
- 不要设计“模型包上传任意 Python 并执行”的流程，这会绕过当前白名单边界。

## 3. 涉及文件

以下以组件 `first_order_actuator` 为例：

| 文件 | 作用 |
| --- | --- |
| `backend/builtin_modules/first_order_actuator.py` | 后端实际执行代码 |
| `backend/builtin_modules/manifest.json` | 模块白名单和接口契约 |
| `backend/tests/test_first_order_actuator.py` | 模块级测试 |
| `public/samples/first_order_actuator_interface.py` | 可选的前端接口描述文件，不在后端执行 |
| 模型包 JSON | 保存画布节点、连线、`pythonBinding` 和参数 |

## 4. 第一步：定义组件接口

编码前先写清以下内容：

| 项目 | 本例取值 | 约束 |
| --- | --- | --- |
| 模块 ID | `first_order_actuator` | 全局唯一，使用小写字母、数字和下划线 |
| 入口函数 | `process` | 默认使用 `process` |
| 业务输入 | `command` | 顺序必须与画布输入端口索引一致 |
| 业务输出 | `actuator_output` | 顺序必须与画布输出端口索引一致 |
| 参数 | `gain`、`timeConstant` | 必须是有限数值并在清单范围内 |
| 状态 | `output` | 每一步返回，下一个时间步继续使用 |
| 中间变量 | `target`、`tracking_error` | 用于诊断和输出追踪，必须是数值 |
| 时间上下文 | `dt`、`time` | 由后端按函数签名自动传入，不属于业务输入端口 |

### 4.1 命名规则

- 文件名、模块 ID、模块注释中的 `Module` 建议一致。
- Python 参数名必须与 `manifest.json` 的输入名和参数名完全一致，包括大小写。
- Python 输出字典中的键必须与清单 `outputs` 完全一致。
- 中文只用于显示名称和说明；模块 ID、函数名、变量名使用英文。
- 不复用已有模块 ID。重复 ID 会在加载清单时由后出现项覆盖前项，形成难以发现的错误。

### 4.2 输入、参数和运行时上下文的区别

- `inputs`：来自上游画布连线，后端按目标端口索引映射到清单中的输入名。
- `parameters`：来自模型节点的数值参数，后端按清单中的范围和默认值解析。
- `time`：当前仿真时间；只有函数签名声明该参数时才传入。
- `dt`：模型包的 `simulationConfig.stepSize`；只有函数签名声明该参数时才传入。
- `state`：该组件上一时间步的状态字典；只有函数签名声明该参数时才传入。

不要把 `time`、`dt` 或 `state` 登记到清单的 `inputs` 中，否则画布会错误地要求为它们连接信号线。

## 5. 第二步：实现后端模块

创建 `backend/builtin_modules/first_order_actuator.py`：

```python
"""
Module: first_order_actuator
Description: First-order actuator with gain and output limiting.
"""


def _clamp(value, minimum, maximum):
    numeric = float(value)
    return max(minimum, min(maximum, numeric))


def process(
    command=0.0,
    gain=1.0,
    timeConstant=0.2,
    dt=0.01,
    time=None,
    state=None,
):
    state = state or {}
    previous_output = float(state.get("output", 0.0))
    target = _clamp(float(command) * float(gain), -1.0, 1.0)
    alpha = _clamp(float(dt) / max(float(timeConstant), 1e-6), 0.0, 1.0)
    actuator_output = previous_output + alpha * (target - previous_output)

    return {
        "outputs": {
            "actuator_output": actuator_output,
        },
        "state": {
            "output": actuator_output,
        },
        "middleVars": {
            "target": target,
            "tracking_error": target - actuator_output,
        },
    }
```

### 5.1 返回结构

推荐使用标准结构：

```python
return {
    "outputs": {"output_name": numeric_value},
    "state": {"state_name": state_value},
    "middleVars": {"variable_name": numeric_value},
}
```

当前后端也接受简单输出映射：

```python
def process(input=0.0, gain=1.0):
    return {"output": float(input) * float(gain)}
```

简单映射适合无状态组件。使用简单映射时，后端会保留当前状态字典，不返回中间变量。

### 5.2 必须遵守的运行规则

- 返回值必须是字典。返回单个数值、元组或列表会触发 `MODULE_SIGNATURE_MISMATCH`。
- `outputs` 和 `middleVars` 中的值必须是有限数值，不能返回 `NaN`、无穷大、字符串或对象。
- 清单声明的每个输出都应显式返回。缺失输出会被后端按 `0.0` 处理，可能掩盖错误。
- 状态只通过传入的 `state` 读取并通过返回值更新，不使用模块级全局变量。
- 不读取本地业务文件、网络、注册表或界面状态。
- 相同输入、参数、状态和时间上下文必须得到相同结果。需要随机扰动时，应由故障运行时处理，或使用显式种子。
- 组件应在单个时间步内快速完成，不能休眠、启动子进程或执行阻塞 I/O。
- `state` 的“实际值”和“参考值”由后端分别保存；组件代码不得把两者放入共享全局对象。

## 6. 第三步：注册模块白名单

编辑 `backend/builtin_modules/manifest.json`，在 `modules` 数组中加入：

```json
{
  "moduleId": "first_order_actuator",
  "importPath": "backend.builtin_modules.first_order_actuator",
  "entryFunction": "process",
  "inputs": ["command"],
  "outputs": ["actuator_output"],
  "parameters": {
    "gain": {
      "type": "number",
      "min": 0.0,
      "max": 10.0,
      "default": 1.0
    },
    "timeConstant": {
      "type": "number",
      "min": 0.001,
      "max": 10.0,
      "default": 0.2
    }
  }
}
```

### 6.1 清单字段说明

| 字段 | 说明 |
| --- | --- |
| `moduleId` | 模型包中的稳定标识；后端按此查找组件 |
| `importPath` | Python 可导入路径，不含 `.py` |
| `entryFunction` | 模块入口函数名称 |
| `inputs` | 业务输入名，数组顺序对应目标输入端口索引 |
| `outputs` | 输出名，数组顺序对应源输出端口索引 |
| `parameters` | 允许从模型包传入的参数、范围和默认值 |

注意：

- 只有清单 `parameters` 中声明的参数会传给函数。
- 模型包中未提供参数时使用清单 `default`。
- 参数低于 `min` 或高于 `max` 会返回 `PARAM_OUT_OF_RANGE`。
- 当前模型节点参数除部分信号源文本字段外都必须是有限数值。
- 清单是 JSON，新增项前后的逗号必须正确。修改后先用 JSON 解析器验证。

验证清单可读取：

```powershell
Get-Content '.\backend\builtin_modules\manifest.json' -Raw |
  ConvertFrom-Json |
  Select-Object -ExpandProperty modules |
  Where-Object moduleId -eq 'first_order_actuator'
```

## 7. 第四步：编写模块测试

创建 `backend/tests/test_first_order_actuator.py`：

```python
import unittest

from backend.module_registry import ModuleRegistry
from backend.schemas import SimulationBackendError


class FirstOrderActuatorTests(unittest.TestCase):
    def setUp(self):
        self.module = ModuleRegistry.from_builtin_manifest().require(
            "first_order_actuator"
        )

    def test_state_persists_across_steps(self):
        first = self.module.call(
            {"command": 1.0},
            {"gain": 2.0, "timeConstant": 0.2},
            dt=0.1,
            time=0.0,
            state={},
        )
        second = self.module.call(
            {"command": 1.0},
            {"gain": 2.0, "timeConstant": 0.2},
            dt=0.1,
            time=0.1,
            state=first["state"],
        )

        self.assertAlmostEqual(first["outputs"]["actuator_output"], 0.5)
        self.assertAlmostEqual(second["outputs"]["actuator_output"], 0.75)
        self.assertIn("tracking_error", second["middleVars"])

    def test_rejects_out_of_range_parameter(self):
        with self.assertRaises(SimulationBackendError) as context:
            self.module.call(
                {"command": 1.0},
                {"gain": 20.0, "timeConstant": 0.2},
                dt=0.1,
                state={},
            )

        self.assertEqual(context.exception.error_code, "PARAM_OUT_OF_RANGE")
        self.assertEqual(context.exception.field, "parameters.gain")


if __name__ == "__main__":
    unittest.main()
```

本例输出限幅为 `1.0`，因此第一次输出为 `0.5`，第二次输出为 `0.75`。

执行单文件测试：

```powershell
uv run python -m unittest backend.tests.test_first_order_actuator -v
```

执行全部后端回归测试：

```powershell
uv run python -m unittest discover backend.tests -v
```

若机器已安装 Python，也可把 `uv run python` 换成 `python`。

### 7.1 测试覆盖要求

至少覆盖：

- 正常输入和输出。
- 参数默认值。
- 参数最小值、最大值和越界值。
- 多时间步状态延续。
- 输出限幅或其他边界行为。
- 返回输出键与清单一致。
- `middleVars` 为数值。
- 状态重置后从初始状态重新运行。
- 若有多个输出，验证每个输出和顺序。

## 9. 第六步：接入前端画布

### 9.1 当前前端绑定的作用

前端“绑定 Python 文件”会解析文件中的模块名、函数输入、返回数量和 `# @observable` 变量，用于生成画布端口和绑定元数据。该操作不会把代码安装到后端。

后端执行时真正起决定作用的是：

- 节点类型必须为 `simulation_block`。
- `pythonBinding.moduleId` 必须等于 `first_order_actuator`。
- 业务输入和输出端口数量、顺序必须与清单一致。
- 模型包中的 `parameters` 必须是数值对象。

### 9.2 准备前端接口描述文件

当前前端解析器面向接口展示，不理解后端标准返回字典中的 `outputs` 键，也会把函数签名中的所有参数当作可见输入。为了避免把 `dt`、`time`、`state` 错误显示成画布输入，建议单独使用一个只描述业务接口的文件。

创建 `public/samples/first_order_actuator_interface.py`：

```python
"""
Module: first_order_actuator
Description: 一阶执行器后端仿真组件
"""


def process(
    command: float  # 输入：执行器指令
) -> float:
    # @observable
    tracking_error = 0.0  # 中间变量：跟踪误差

    actuator_output = command
    return actuator_output  # 输出：执行器输出
```

该文件仅用于前端接口解析，后端实际执行的仍是 `backend/builtin_modules/first_order_actuator.py`。

### 9.3 在平台中绑定

1. 启动后端：`uv run python -m backend.server`。
2. 启动前端：`npm.cmd run dev`。
3. 在画布中放置一个“仿真块”，不要使用 `flow_block` 作为后端执行组件。
4. 选中仿真块，在属性区点击“绑定 Python 文件”，或双击未绑定的仿真块。
5. 选择 `first_order_actuator_interface.py`。
6. 检查模块名为 `first_order_actuator`、入口为 `process`。
7. 检查只有一个业务输入和一个业务输出；`tracking_error` 显示为中间变量。
8. 点击“确认绑定”。
9. 连接信号源到输入端口，连接输出端口到示波器。
10. 导出或运行后端仿真前，检查可执行模型包。

如果使用“新增仿真组件”对话框保存为组件模板，还需填写中文名称、组件类别、几何形状和默认故障槽位。该对话框是否在当前发布界面提供直接菜单入口，以实际版本为准；没有入口时可先绑定现有仿真块完成联调。

### 9.4 检查导出的可执行模型包

对应节点至少应为：

```json
{
  "id": "actuator-1",
  "type": "simulation_block",
  "parameters": {
    "gain": 2.0,
    "timeConstant": 0.2
  },
  "inputs": [
    {"name": "command"}
  ],
  "outputs": [
    {"name": "actuator_output"}
  ],
  "pythonBinding": {
    "moduleId": "first_order_actuator",
    "entryFunction": "process"
  }
}
```

当前前端对自定义参数的自动表单支持有限。若导出的 `parameters` 没有 `gain` 或 `timeConstant`：

- 先使用 `manifest.json` 中的默认值完成执行验证；或
- 在组件模板/属性面板契约中加入对应数值属性，再确认导出服务能读取这些属性；或
- 由受控的模型包生成工具写入参数。

不要把参数数组、字符串数字或嵌套表单对象直接放入后端 `parameters`。后端要求这里是“参数名 -> 有限数值”的对象。

## 10. 第七步：适配故障注入

### 10.1 参数故障

对清单参数注入偏置、阶跃或漂移时，故障实例应指定组件节点和参数键。例如：

```json
{
  "faultId": "actuator-gain-bias",
  "faultType": "parameter_bias",
  "targetId": "actuator-1",
  "injectionForm": "module-variable",
  "parameterKey": "gain",
  "enabled": true,
  "startTime": 0.1,
  "duration": 0.2,
  "parameters": {
    "bias": -0.3
  }
}
```

约束：

- `parameterKey` 必须是清单中已声明的参数。
- 故障后的参数仍应落在业务可接受范围内；若经运行时修改后超出组件逻辑容许范围，应在组件内做物理限幅并补测试。
- 后端对实际值路径应用参数故障，参考值路径保持基线参数。

### 10.2 输出信号故障

组件节点可以作为偏置、噪声、卡死等信号故障的目标。当前执行引擎的节点级输出故障作用于组件的主输出，也就是输出索引 0。多输出组件若需要对特定非主输出精确注入故障，应先确认现有故障运行时是否支持该端口级目标，不要默认所有输出都会被修改。

### 10.3 故障槽位

若组件要在前端故障库中可选，应在组件模板中声明对应槽位：

- 参数故障：槽位类型 `parameter`，目标字段对应参数名。
- 输入信号故障：槽位类型 `input_signal`。
- 输出信号故障：槽位类型 `output_signal`。
- 内部状态故障：槽位类型 `state_variable`，需确认后端故障运行时已有对应行为。

槽位负责前端兼容性和可视化筛选；后端最终仍根据模型包中的 `faultInstances` 执行故障。

## 11. 多输入、多输出和反馈环注意事项

### 11.1 端口顺序

后端按端口索引而不是中文显示名传值：

```text
targetPortIndex 0 -> manifest.inputs[0]
targetPortIndex 1 -> manifest.inputs[1]
sourcePortIndex 0 -> manifest.outputs[0]
sourcePortIndex 1 -> manifest.outputs[1]
```

改变清单数组顺序属于不兼容变更，可能让旧模型包把信号接到错误变量。已有模型投入使用后，应新增模块版本，而不是直接重排端口。

### 11.2 反馈环

若模型存在环路，当前后端在检测到递归依赖时使用上一时间步的值。组件设计应：

- 明确初始状态。
- 测试第一个时间步和后续时间步。
- 避免对 `dt` 过度敏感导致数值不稳定。
- 在支持的步长范围内测试收敛性。

### 11.3 多输出

多输出模块必须返回全部清单输出：

```python
return {
    "outputs": {
        "position": position,
        "velocity": velocity,
    },
    "state": {
        "position": position,
        "velocity": velocity,
    },
    "middleVars": {},
}
```

清单：

```json
"outputs": ["position", "velocity"]
```

## 12. 模型包和性能限制

当前后端主要限制：

| 项目 | 限制 |
| --- | ---: |
| 仿真时长 | `0 < duration <= 1000.0` |
| 步长 | `1e-12 <= stepSize <= 1.0` |
| 完整运行总样本数 | 不超过 100,000 |
| 分步会话单次返回样本数 | 不超过 1,000；时间线总步数不受完整运行上限限制 |
| 分步会话空闲超时 | 900 秒；后端定时主动回收 |
| 节点数 | 不超过 200 |
| 连线数 | 不超过 400 |
| 故障实例数 | 不超过 50 |
| 测量点数 | 不超过 100 |

组件每个时间步至少会分别在实际值和参考值路径上执行。增加测点、组件或复杂计算会放大总耗时。接入计算量较大的组件时，应记录：

- 单次完整仿真的耗时。
- 不同 `duration` 和 `stepSize` 下的耗时。
- 多客户端并发时的 CPU、内存和响应时间。
- 组件异常时是否快速失败并返回可定位错误。

## 13. 常见错误及定位

| 错误码/现象 | 原因 | 检查项 |
| --- | --- | --- |
| `MODULE_NOT_WHITELISTED` | 模块 ID 未注册 | `pythonBinding.moduleId`、清单模块 ID、部署版本、后端是否已重启 |
| `MODULE_SIGNATURE_MISMATCH` | 入口不存在或返回结构错误 | `entryFunction`、函数是否可调用、返回是否为字典、`outputs/state/middleVars` 类型 |
| `PARAM_OUT_OF_RANGE` | 参数超出清单范围 | 模型包参数、清单 `min/max`、故障后的参数值 |
| `INVALID_SCHEMA` | 参数不是有限数值或模型结构错误 | JSON 类型、`parameters`、端口字段、`schemaVersion` |
| `UNSUPPORTED_NODE_TYPE` | 节点类型后端不支持 | 确认使用 `simulation_block` |
| 输出始终为 0 | 输出键缺失、端口错误或上游未连接 | 清单输出名、返回键、端口索引、`componentOutputs` |
| 状态每步重置 | 未返回状态或使用了错误状态键 | `state` 输入、返回的 `state`、模块级全局变量 |
| 实际和参考互相影响 | 使用共享全局状态 | 移除全局缓存，只使用传入/返回状态 |
| 前端显示端口过多 | 直接绑定了包含 `dt/time/state` 的后端文件 | 使用单独的前端接口描述文件 |
| 前端可见但后端失败 | 只完成了前端绑定 | 部署后端 `.py` 和清单并重启服务 |

快速检查白名单：

```powershell
uv run python -c "from backend.module_registry import ModuleRegistry; print(sorted(ModuleRegistry.from_builtin_manifest().modules))"
```

快速直接调用：

```powershell
uv run python -c "from backend.module_registry import ModuleRegistry; m=ModuleRegistry.from_builtin_manifest().require('first_order_actuator'); print(m.call({'command':1.0},{'gain':2.0,'timeConstant':0.2},dt=0.1,state={}))"
```

## 14. 发布到其他机器

新增组件发布时必须同步以下内容：

1. `backend/builtin_modules/first_order_actuator.py`。
2. 修改后的 `backend/builtin_modules/manifest.json`。
3. 新增或修改的后端测试。
4. 若前端需要接口描述或组件模板，发布新的 `dist/`。
5. 使用该组件的模型包或模型包生成工具。
6. 变更说明，包括模块 ID、接口、参数范围和兼容性。

发布步骤：

1. 在构建机运行模块测试和全部后端测试。
2. 运行前端测试、构建和 UI 审计。
3. 用最小模型包执行 API 冒烟测试。
4. 按《故障注入平台 Windows 正式部署操作手册》生成新版本目录。
5. 在维护窗口切换版本并重启后端服务。
6. 通过 IIS 地址重新执行 API 冒烟测试。
7. 在浏览器加载含新组件的模型，检查曲线、状态和故障响应。
8. 失败时整体回滚到上一版本，不只回滚 `.py` 或清单中的一部分。

## 15. 接入完成检查表

- [ ] 模块 ID 唯一，文件名、模块注释和清单一致。
- [ ] 业务输入、输出和参数已经书面定义。
- [ ] `dt`、`time`、`state` 没有误登记为业务输入。
- [ ] 后端模块只使用参数、输入和显式状态，不依赖外部 I/O。
- [ ] 返回值是字典，输出键与清单完全一致。
- [ ] 有状态组件分别验证了第一步和后续步骤。
- [ ] `manifest.json` 可解析，参数默认值和范围合理。
- [ ] 模块级测试通过。
- [ ] 全部后端回归测试通过。
- [ ] 最小模型包 API 冒烟测试通过。
- [ ] 前端节点类型为 `simulation_block`。
- [ ] `pythonBinding.moduleId` 与白名单一致。
- [ ] 端口数量和顺序与清单一致。
- [ ] 导出模型包中的参数是有限数值对象。
- [ ] 实际值和参考值状态隔离已验证。
- [ ] 参数故障或输出故障行为已验证。
- [ ] 新组件、清单、前端产物和模型包作为一个版本发布。
- [ ] 目标机器后端已重启并通过 IIS 地址验收。
