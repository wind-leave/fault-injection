# 手动模型测点、多信号流图和 D 矩阵流程

## 目标

手动搭建系统时，不依赖飞控 demo 的固定诊断数据。平台应从当前画布的节点、连线和已注入故障中生成候选诊断数据，但测点必须由用户明确添加。

## 层级方案

1. 系统拓扑层：用户在画布中放置模块，并通过普通连接线或 CAN 总线连接端口。
2. 测点层：有效连线只进入“候选连线”列表，不能自动成为固定测点；用户选择某条连线并点击“添加测点”后，才生成固定测点。
3. 故障层：物理层、电气层、协议层故障绑定后，作为当前画布的故障模型进入诊断库。
4. 多信号流图：读取当前候选连线和已添加测点，用户先添加需要观测的测点，再逐个安装或一键安装已添加测点。
5. D 矩阵：只读取已添加的测点和当前故障模型，按故障影响链路生成 0/1 可检测关系。

## 操作流程

1. 点击“新建空白模型”，拖入系统模块。
2. 用端口建立信号连接；需要协议故障时使用 CAN 总线连接。
3. 切换到“多信号流图”，每条有效连线会出现在“候选连线”下拉栏。
4. 选择需要观测的连线并点击“添加测点”，该测点才进入“固定测点”列表。
5. 点击单个固定测点完成安装，或点击“全部安装”快速安装已添加的测点集。
6. 放置物理层、电气层或协议层故障组件，点击“绑定目标”，选择模块或连线并确认故障参数。
7. 切换到“D矩阵”，平台按当前已添加测点和当前故障生成矩阵。
8. 在多信号流图中点击“检测故障”，可按已安装测点查看候选故障并人工确认。

## 实现路径

- 测点来源：`buildDiagnosticTestPointModel()` 返回 `candidateEdges` 作为候选连线，`positions` 只包含用户通过 `addDiagnosticTestPointFromEdge()` 手动添加的测点。
- 故障来源：`getRuntimeFaultLibrary()` 合并模型包故障、已加载故障和当前画布实际故障。
- 手动模型隔离：空白模型不再自动混入飞控 demo 的故障库。
- D 矩阵来源：`buildDetectionMatrixModel()` 使用已添加测点和故障影响链路生成矩阵，不再把所有有效连线自动列入矩阵列。
- 回归验证：新增手动模型测试，覆盖空白模型、手动连线、测点安装、当前故障和 D 矩阵生成。
