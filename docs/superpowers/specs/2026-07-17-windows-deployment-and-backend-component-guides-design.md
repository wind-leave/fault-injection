# 故障注入平台 Windows 部署与后端仿真组件文档设计

## 1. 目标

基于当前故障注入平台的实际代码、目录和接口，编写两份可直接执行的 Markdown 操作手册：

1. `docs/故障注入平台Windows正式部署操作手册.md`
2. `docs/后端仿真组件创建与接入流程.md`

文档面向需要在其他 Windows 机器上长期运行平台的部署人员，以及需要新增后端可执行仿真组件的开发人员。

## 2. 已确认范围

- 目标操作系统：Windows，重点覆盖 Windows Server，也兼容 Windows 10/11 的内网部署。
- 使用场景：长期运行的正式部署，不以 Vite 开发服务器作为生产入口。
- 交付格式：仅 Markdown，不生成 Word 或 PDF。
- 部署架构：IIS 托管前端静态文件，`/api/*` 反向代理至本机 Python 后端；Python 后端由 Windows 服务包装器托管。
- 后端组件：仅说明能够被当前 `backend.server` 白名单加载并参与后端仿真的组件，不把前端内嵌 Python 源码误写成可直接执行代码。

## 3. 文档一设计

《故障注入平台 Windows 正式部署操作手册》采用“准备、安装、配置、验收、运维”的顺序，包含：

- 当前架构和生产部署拓扑。
- 硬件、软件、账号、端口及目录规划。
- 在开发机生成前端 `dist/` 发布产物，并整理完整后端发布包。
- 在目标机安装 Node.js（仅在目标机构建时需要）、Python、IIS、URL Rewrite、ARR 和 Windows 服务包装器。
- IIS 静态站点、默认文档、MIME、反向代理和同源访问配置。
- 将 `python -m backend.server` 注册为开机自启服务。
- Windows 防火墙最小开放原则：只开放对外 Web 端口，后端 8766 保持回环监听。
- 前端、后端、模型资源和 API 的分层验收。
- 日志、备份、版本化发布、原子切换、回滚和日常巡检。
- 典型故障：页面空白、静态资源 404、API 404/502、服务无法启动、模块白名单错误、端口占用和浏览器缓存。

文档中的命令以 PowerShell 为主。外部工具路径、站点名和安装目录使用统一示例值，并明确哪些值需要按现场修改。

## 4. 文档二设计

《后端仿真组件创建与接入流程》采用“设计接口、实现模块、注册白名单、测试、平台绑定、联调发布”的顺序，包含：

- 当前执行链：前端画布导出可执行模型包，后端按 `moduleId` 从内置清单加载 Python 模块。
- 安全边界：模型包中的 Python 源码不会被后端执行，组件必须部署到 `backend/builtin_modules/` 并登记在 `manifest.json`。
- 命名、输入、输出、参数、`time`、`dt`、`state`、`middleVars` 的规范。
- 无状态组件和有状态组件的完整代码示例。
- 返回结构要求：简单输出映射，或包含 `outputs`、`state`、`middleVars` 的标准结构。
- `manifest.json` 注册示例，以及输入输出顺序和画布端口索引的对应关系。
- 单元测试、最小模型包测试、完整后端测试和 HTTP API 冒烟测试。
- 在前端创建 `simulation_block`、配置端口、参数和 `pythonBinding` 的流程。
- 故障注入适配、参数范围、确定性、状态隔离、循环反馈和性能限制。
- 发布清单、常见错误码及定位方法。

示例组件统一使用一个带增益、限幅和一阶状态的执行器组件，使参数、状态和中间变量能够在一个完整示例中体现。

## 5. 准确性约束

- 以当前代码为准，不直接照抄已过时的示例。当前后端要求模块返回字典，且模块必须在 `backend/builtin_modules/manifest.json` 白名单中。
- 当前后端默认监听 `127.0.0.1:8766`，正式部署通过 IIS 代理访问，不直接暴露该端口。
- 当前生产静态服务器脚本不代理 `/api`，因此不能把 `serve-dist-local.mjs` 直接作为完整生产入口。
- 前端接口使用相对路径，IIS 必须将 `/api/*` 转发到后端，保证前后端同源。
- 不在文档中写入现场密码、私钥或固定域名。

## 6. 验收标准

- 两份文档均可独立阅读并按步骤执行。
- 所有命令、路径、JSON 和 Python 示例格式完整，无 `TODO`、`TBD` 或占位章节。
- 部署文档覆盖首次部署、升级、回滚和故障排查。
- 组件文档覆盖实现、注册、测试、画布绑定、API 联调和发布。
- 文档内容与当前 `package.json`、`vite.config.js`、`backend/server.py`、`backend/module_registry.py`、`backend/builtin_modules/manifest.json` 和测试代码保持一致。
